Video Studio · Plugin 0.2.0

Voice first. Visuals timed to the words.

How to take a brief to a mastered, narrated product video with the video-studio plugin — a workflow proven across a family of shipped pitch films.

VO → WORDS → COMP → RENDER → MUX → BED → MASTER
Audio-locked · the voice is generated first, everything else is timed to it
Getting started

Install once, doctor the machine

From a clone of the plugin repo, in any terminal:

claude plugin marketplace add /path/to/video-studio
claude plugin install video-studio@video-studio

Then, inside Claude Code, run the environment doctor:

/video-setup

It checks the four dependencies and prints a PASS / FIX table with the exact command for anything missing:

DependencyWhy the pipeline needs it
node ≥ 20Runs the hyperframes CLI. On WSL it must be the Linux nvm build — a Windows node on the PATH breaks rendering.
hyperframes CLITTS voice, comp linting, checks, and headless rendering. Auto-installs on first npx hyperframes use.
ffmpeg + ffprobeEvery audio measurement, mux, and the final master.
python3 + faster-whisperWord timestamps from the voiceover. CPU-only — no GPU or CUDA required.

The doctor never runs sudo. If it prints a sudo line (e.g. installing ffmpeg), run it yourself by typing it with a ! prefix in the Claude Code prompt, then run /video-setup again.

The workspace

Four folders, per-project subfolders

Start every project with:

/video-new my-project

That scaffolds this tree in your working directory. Everything the project ever touches lives in one of the four top-level folders:

context/my-project/         # every textual input — briefs, pasted docs, specs
  BRIEF.md
  feedback/                 # each review round: YYYY-MM-DD-who.md
assets/my-project/          # every binary input — logos, screenshots, recordings
build/my-project/main/      # ONE live scene tree per cut
  script/v1.md v2.md …      # SOURCE — VO + beat sheet + changelog per version
  sec1/ … secN/
    comp/index.html         # SOURCE — the animated composition
    vo/p1.wav  words.json   # derived — safe to delete, regenerates
    comp.mp4   secN.mp4     # derived
  gen_vo.py                 # SOURCE — the voiceover script lives here
  gen_bed.py  final.mp4     # bed generator · derived master
videos/my-project/
  current/                  # the latest shipped mp4(s) + README.md
  versions/                 # every previous ship — append-only

The red items are source of truth; the grey derived files are disposable and regenerate from them. That split is what makes re-renders and client forks cheap.

Your look

Bring your own design.md

Every visual decision — palette, typography, watermark, end lockup, even the VO voice — comes from one design doc. Drop your own design.md into context/<project>/ and the whole project follows it; without one, the plugin's clean built-in default applies (dark #101318 / light #F4F3F0 moods with a single red accent, grotesk display + mono labels).

Cover the same headings as the default — Palettes, Type, Marks, Voice — and anything you leave out falls back to the default's value. Hand the file to the agent at /video-new time, or any time before the first comp is built.

The six rules

Non-negotiables the skills will hold you to

R1

Move inputs in before using them

Anything the user pastes or drops — a Slack thread, a screenshot, a spreadsheet — is saved into context/ (text) or assets/ (binary) with a dated name before it's used. Never work from chat scrollback or loose files in the repo root.

R2

Rotate on every ship

Previous deliverables move from current/ to versions/ (append-only), the new mp4 lands in current/, and the README is rewritten. current/ always answers “what's the latest and why”.

R3

Version the script, then edit

Every VO or visual change gets a new script/vN.md — full VO, beat sheet, and what changed. The doc drives the edit, never the other way round.

R4

Know source from derived

Comps, the gen_vo SPEC, scripts, context and assets are source. Wavs, words.json, renders, muxes, bed and final are derived — delete freely; the pipeline regenerates only what's missing.

R5

Audio-locked order, whole-block edits

VO first, whisper words second, comp timeline last. When narration changes, rewrite the entire timeline block to the new word times — patching individual time literals corrupts timelines silently.

R6

Gates before shipping

Show-don't-tell (on-screen copy never prints the VO sentence), privacy-mask real names and paths in recordings, hyperframes check must pass, and every changed beat is verified by eye from rendered frames.

The build loop

One scene, start to finish

Repeat per scene, working in build/<project>/<cut>/. You mostly describe what you want and the agent runs these — but this is what's happening, and what to check at each step.

  1. Write the script version

    script/v1.md: the narration in full, plus a beat sheet — which word triggers which visual. Get this approved before building; changing a comp is 10× the cost of changing a sentence.

  2. Generate the voiceover

    Put the narration into the SPEC dict in gen_vo.py as breath groups — one phrase per string, pause lengths as floats between them — then python3 gen_vo.py. Kokoro af_sky at 0.80 reads it. Pronunciation is fixed by rephrasing, never respelling: hyphenate initialisms (“A-I”, “S-D-K”), spell tricky brand names phonetically in the SPEC only, and swap words the voice mangles. Existing wavs are skipped — delete a wav to regenerate it.

  3. Extract word timestamps

    python3 whisper_words.py sec1/vo/p1.wav sec1/words.json. Mis-heard words are fine — only the timings are used.

  4. Build the composition

    Copy the skeleton from the comp-craft skill into sec1/comp/index.html. Every beat lands at its trigger word's start + 0.3 s (the mux lead). Initial offsets go in GSAP fromTo, never CSS transform — lint rejects that.

  5. Lint, check, render

    npx hyperframes lint  sec1/comp
npx hyperframes check sec1/comp   # runtime · overlap · motion · contrast
npx hyperframes render sec1/comp -o sec1/comp.mp4 -w 2

    One comp at a time, always -w 2. Then extract stills at each beat and actually look at them.

  6. Mux the voice onto the render

    Measure the VO's loudness, apply static gain to −18 LUFS with a limiter, delay 300 ms, mux. The exact command lives in the mix-master skill — never use adaptive loudnorm on narration; it pumps in the gaps.

Shipping

From sections to a deliverable

/video-ship my-project

Runs the ten-step checklist: verify gates → concat sections → regenerate the music bed at the exact final duration → master (bed ducks under the voice, limiter, −3.5 dB trim) → verify ≈ −16.9 LUFS / −3.8 dBTP → name it <Project>-vN.mp4 → rotate current/ → rewrite the README → hand you the file. If loudness lands outside −16…−18 LUFS, only the final volume= is adjusted — never the limiter.

Forks

A different cut for a different client

Same film, different framing — a client-specific platform beat, a different destination story. Don't rebuild; fork the cut:

  1. Copy the live tree

    build/my-project/main/ → build/my-project/client-x/, whole.

  2. Delete only what changes

    For each scene that differs, delete its derived files (wav, words.json, renders, mux). Untouched scenes keep their outputs byte-identical.

  3. Re-run the loop

    Edit the SPEC and comps for the changed scenes; the skip-if-exists VO generator regenerates only what's missing. Re-ship. A full fork of a 4-minute film is an afternoon, not a week.

Field notes

Gotchas that already cost a day each

SymptomCause and fix
Respelled word still mispronounced Kokoro collapses respellings back to the original (“livz” → “lives”), and IPA gets read aloud. Rephrase — use a different word.
faster-whisper crashes on libcublas It tried the GPU. Always device='cpu', compute_type='int8' — the shipped whisper_words.py already does this.
Timeline subtly wrong after a retime Someone patched individual time literals. Rewrite the whole timeline block from words.json (rule R5).
Lint error about CSS transform Initial offsets belong in tl.fromTo(el, {y:24}, {…}), not transform: translateY in CSS.
Contrast warning mid-animation A false positive sampled mid-tween between two valid states. If both end states pass and check passes overall, leave it.
Master clips past −3 dBTP Static gain with no limiter. The mux command's alimiter=limit=0.7079 is not optional.
Privacy blur slides off its target ffmpeg -ss isn't frame-exact. Use trim= filters and always-on masks.
